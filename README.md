# SpMM_cuda加速实现

### 基本实现方法
#### 1. 避免warp divergence
ref代码中每个线程处理一行的计算，由于矩阵稀疏，这就导致一个warp中的不同线程都在做不同的计算，极大地降低了计算效率。因此实际计算时，每个warp的不同线程应该计算稀疏矩阵的同一行，分别对应与之相乘的矩阵的32列，这样就避免了warp divergence。实际代码中，对于len=32的情况可以直接这么做，对于len=256的情况，需要每个线程计算完一列后跳到32列后，循环完成计算。
#### 2. 合理分配线程块
大多数稀疏矩阵中，有些行非常稠密，有些则非常稀疏，因此需要根据实际情况分配合理的线程块个数。每一个线程块大小设置为32，而每个线程块处理特定长度的序列。例如对于len=32时，每个线程块处理的序列长度为64，因此需要将一行划分成多个长度为64的序列（最后一段序列可能达不到64），对于那些非零元不超过64的行认为是稀疏行，只分配一个线程块，对于超过64的行则分配多于一个线程块，这样合理分配能够加速计算效率。这里的序列长度64是通过多次调整参数试出来的一个合适值。对于len=256的情况，由于每个线程块的计算量由原本的32变成256，因此为了平衡计算量将序列长度设置为32，通过参数调整这也是试出来的最合适的长度。
#### 3. 利用共享内存
将稀疏矩阵中的每一个分段好的序列，将这些元素存储进共享内存中，能够极大提高访存效率，对于与之相乘的稠密矩阵由于只需要访问一次，因此不需要多此一举，并且实际情况也没有足够大的共享内存来存储这些值。
#### 4. 增大数据访问局部性
经过对每一行的切分后，实际每个线程块需要计算的只是一小段序列，这每一小段序列如果通过合适的调整计算顺序可以极大提高访存效率。具体而言，每一小段序列可以根据其对应的idx来进行排序，这样排完序后每个线程块计算时会频繁访问到稠密矩阵的相同的元素，从而提高L2Cache的利用率，增加全局内存的访问效率。
#### 5. 特殊优化方法
我注意到有些特殊矩阵如wikikg2的idx有许多相同的值，因此可以在预处理时将相同idx的val相加合并，对这种特殊矩阵能够有比较大的提升。一般的矩阵没有此问题。

### 不同优化方法对效率的影响
上面提到的前4类方法对所有矩阵都是普适性的，因此使用后都能得到一定提高。不过第四种方法尤其对更为稠密的矩阵有效。对于稠密矩阵reddit.dgl，使用该方法前，对len=256时计算需要耗费0.2s左右，使用后大约0.11s，性能得到了大幅提升。对于非常稀疏的矩阵，如果几乎所有行都是稀疏行，那么该方法提升较为有限。因为稀疏的行idx本身就重复率不高，对访存效率提升不明显。
对wikikg2的特殊优化方法几乎仅对其有效，len=256的情况下，使用该方法前运行耗费17000us左右，使用后仅运行了10000us左右，有比较大的提升。
